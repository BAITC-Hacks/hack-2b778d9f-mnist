# План доведения MVP до требований HackAlem

Дата: 23 сентября 2026 года. Источники: [задание трека](../track/HackAlem%20AI_%20Система%20автопротоколирования%20совещаний%20с%20фиксацией%20поручений.md), [функциональная спецификация](../spec-meeting-minutes-assistant.md), [модель предметной области](../CONTEXT.md). Исследование выбранных моделей: [первичные источники и ограничения](research/2026-09-23-model-selection.md).

Статус: инженерная реализация основного сценария готова, качество моделей имеет ограничения и продолжает проверяться. P0 выполнен; P1 выполнен частично; P2 отложен. Проход конвейера до экспорта не означает полного соответствия языковым требованиям или правильности каждого поручения.

Основной стек — официальный Whisper Large-v3 Turbo через Transformers, Community-1 и Ollama/Qwen3-8B. Результаты конкретных прогонов, настройки, измерения и выявленные ошибки фиксируются в [отчёте об испытаниях](../evaluation/2026-09-23-results.md). Этот отчёт является источником актуальных метрик; предварительные показатели здесь не дублируются.

## Что оценивает трек

| Обязательство | Проверяемый результат |
| --- | --- |
| Русский, казахский и смешанная речь | Отдельная разрешённая запись каждого типа проходит полный конвейер; сохранены имена, числа и смысл поручений |
| Диаризация и привязка к человеку | Реплики различаются по speaker ID; человек может подтвердить имена; ответственный не подменяется говорящим |
| Автоматические поручения | Извлечены действие, явно назначенный исполнитель, срок как сказано и основание; отсутствующие поля видны |
| Саммари и транскрипт | Содержание доступно для проверки и правки, спорные фрагменты можно прослушать |
| Экспорт | Скачивается пригодный DOCX или PDF с сохранёнными правками; неподтверждённый результат помечен черновиком |
| Локальное выполнение и приватность | Аудио и производный текст не уходят во внешние AI API; разрешённые материалы хранятся локально и удаляются вместе с записью |
| Воспроизводимость | Репозиторий содержит приложение, зависимости, пути моделей, запуск и сценарий проверки |

Работоспособность, техническая реализация и README/воспроизводимость дают по 25 баллов, применимость — 15, развитие и оригинальность — 10. Поэтому готовый основной сценарий и проверяемая инструкция имеют преимущество перед расширением интерфейса.

Live-захват, подключение к конференциям, дашборд исполнения, напоминания, СЭД, рассылка и биометрическая идентификация отложены до выполнения обязательного сценария. Вход записью предусмотрен треком. Возможность локального размещения остаётся требованием; полноценное промышленное развёртывание не входит в минимум. Brev используется для разрешённого демо и сам по себе не подтверждает закрытый контур заказчика.

## Аудит исходного решения

Архитектура React/Vite + FastAPI + SQLite + файлы + один последовательный обработчик подходит для одной демо-машины. Сохраняем локальные ASR/диаризацию/LLM, ссылки на реплики, человеческие правки и маркировку черновика. Неопределённость исполнителя, времени или голоса должна оставаться видимой.

| Обнаруженный разрыв | Последствие | Принятое исправление |
| --- | --- | --- |
| Код находился в `/tmp`, корневой README не описывал приложение | Проверяющий не может воспроизвести решение из репозитория | Перенос приложения и точный README |
| Только WAV при штатных MP3 трека | Невозможно загрузить предоставленные записи | Локальное декодирование MP3, проверка размера, длительности и реального формата |
| Имя из списка участников считалось достаточным подтверждением ответственного | Возможное выдуманное назначение | Проверять свидетельство в репликах, иначе сохранять неопределённость |
| Срок нормализовался без подтверждения исходной фразой | Ложная дата в протоколе | Сохранять фразу, проверять источник, нормализовать только однозначные выражения |
| Неполная валидация вложенных PATCH-полей | Повреждённые правки, ссылки или экспорт | Проверять типы, даты, временные интервалы, ссылки и человеческое подтверждение |
| При отказе PDF интерфейс терял доступ к готовому DOCX | Основной сценарий блокировался дополнительным форматом | Показывать доступный документ и отдельную ошибку конвертации |
| Один интервал диаризации должен был полностью покрывать ASR-сегмент | Паузы и погрешности границ скрывали даже единственного говорящего | Сопоставлять покрытие; настоящие смены голоса и наложения показывать отдельно |
| Пути ASR в инструкции не совпадали с загрузкой; окружение моделей не закреплено | Запуск из инструкции мог не работать | Согласованные каталоги, предварительная проверка артефактов и запись версий |
| Тесты использовали заменители моделей | Зелёные тесты не доказывали RU/KK/mixed качество | Отдельные реальные прогоны по матрице evaluation |

Это перечень исходных проблем и решений. Инженерные исправления прошли проверки P0. Отдельная содержательная оценка моделей относится к P1.

## Приоритеты и критерии приёмки

### P0 — воспроизводимый основной сценарий: выполнен

1. Приложение включено в рабочий репозиторий; зависимости, переменные окружения и пути моделей согласованы; обработка выполняется одним backend worker.
2. Реализована загрузка WAV и штатных MP3 с проверками размера, формата и длительности до моделей.
3. Исправлены проверки основания ответственного и срока, валидация правок и доступность DOCX при отказе PDF. Фраза без года остаётся на уточнение; список участников не устанавливает голос или назначение.
4. Реализован цикл проверки человеком: прослушивание основания, исправление, сохранение, повторное открытие и скачивание. Предложение без проверенного подтверждения остаётся кандидатом.

Проверка P0: прошли 92 backend-теста и 16 frontend-тестов, frontend build успешен. Проверяются приём MP3, сохранность правок после перезапуска, экспорт сохранённого содержания, DOCX при отказе PDF и удаление записи с файлами. Команды доступны в README. Эти проверки подтверждают инженерное поведение; часть тестов использует подмены моделей и не измеряет качество речи или извлечения.

### P1 — реальная модельная проверка: частично выполнена

Обе предоставленные русскоязычные записи уже прошли полный конвейер с локальными моделями и экспортом в Linux network namespace с запрещённым внешним доступом. Повторные прогоны с русским промптом завершены и содержательно проверены: выявлены ошибки извлечения. После них улучшено объединение коротких ASR-фрагментов; повтор этой последней правки на GPU остановлен потерей SSH-доступа к Brev.

Созданы короткие казахский и составной смешанный TTS-примеры; их модельные прогоны завершены с ошибками извлечения и распознавания, перечисленными в отчёте. Они дополняют матрицу, но не являются записью естественного многостороннего совещания. В составном примере одновременно меняются язык и синтетический голос.

Оставшаяся работа:

1. После восстановления доступа повторить изолированный прогон обеих записей с текущими границами ASR; записать версии, ревизии, параметры и результаты в отчёт.
2. Сопоставить поручения с [матрицей](../evaluation/cases.json). Разногласия эталонов разрешать прослушиванием. Считать отдельно пропуски, ложные поручения, исполнителей и сроки.
3. Проверить TTS-аудио прослушиванием до оценки ASR, затем проверить казахский и составной mixed-примеры. Не считать ожидаемый текст синтеза гарантированно правильной расшифровкой его аудио.
4. Проверить естественную казахскую и смешанную речь с несколькими участниками, перебиваниями и разными голосами по [собственным сценариям](../evaluation/simulated.json). Для этой проверки ещё нужны разрешённые записи и ручная разметка.
5. Завершить ручную оценку транскрипта, саммари, поручений и экспорта, включая казахские символы; проверить неизвестного исполнителя, неоднозначные сроки, тишину и наложение речи.

Критерий полной приёмки P1: каждый заявленный случай имеет аудио, настройки, результат и ручную оценку; отдельно записаны пропуски/ложные поручения, ошибки исполнителей/сроков, спорные голоса, время и VRAM. Невыполненные проверки обозначены `pending`. Остаточные ошибки перечисляются, неопределённые значения не представлены как факты. Проценты качества публикуются только с числителем, знаменателем и правилами оценки. Текущий технически успешный прогон не закрывает автоматически этот критерий.

### P2 — удобство и развитие: отложен

Сначала устранять обнаруженные ошибки распознавания, говорящих и поручений: они напрямую влияют на обязательные требования трека. После содержательной оценки выбирать одно расширение: надёжный захват микрофона с последующей полной обработкой либо дашборд проверенных поручений. Live-превью требует отдельных проверок целостности фрагментов, задержек и очереди GPU. Рассылка и интеграции относятся к дополнительным возможностям; сейчас приоритет имеют качество и воспроизводимость основного сценария.

## Что ещё требует доказательств

- Повторный GPU-прогон после изменения объединения коротких ASR-фрагментов.
- Исправление выявленных ошибок извлечения на RU/KK/mixed; точные WER/CER и ошибки диаризации не измерены.
- Естественная казахская/смешанная речь с несколькими голосами и наложением: требуются разрешённые записи и ручная разметка.
- Визуальная проверка экспортированных PDF, включая казахские символы.

Завершённые прогоны, измерения и ограничения зафиксированы в [отчёте](../evaluation/2026-09-23-results.md). Инженерная реализация готова к воспроизводимому использованию и дальнейшей оценке; полное качество языковых сценариев пока не подтверждено.
