# Локальные модели для протоколирования: проверка выбора

Дата проверки первичных источников: 23 сентября 2026 года. Документ объединяет исследование документации и исходного кода с результатами диагностического прогона команды. Полная сравнительная оценка языков и моделей ещё не завершена.

## Решение для MVP

Исходная конфигурация: `shyngys879/kazakh-whisper-large-v3-turbo` для ASR, локальный `pyannote/speaker-diarization-community-1` для диаризации, локальный `qwen3:8b` через Ollama для извлечения и саммари. Её выбрали для первого сквозного испытания с существующими адаптерами. После обнаруженной ошибки ASR выбор распознавания пересматривается; сравнительный кандидат — `openai/whisper-large-v3-turbo`. До результатов сравнения окончательный ASR не выбран. Диаризация и извлечение сохраняются для продолжения испытаний.

Поддержку всего обязательного сценария считать подтверждённой только после отдельных проверок русского, казахского и смешанной речи. Если выбранный ASR теряет русские фразы или переключения языков, менять конфигурацию по результатам сравнения на тех же записях. До этого не добавлять ансамбль, автоматическое переключение ASR или более крупную LLM.

## ASR: Kazakh Whisper Large-v3 Turbo

Автор описывает модель как дообученный на казахской речи полный Transformers checkpoint на базе Whisper Large-v3 Turbo, около 0,8 млрд параметров, с лицензией Apache-2.0. Карточка содержит казахские оценки FLEURS и внутреннего набора, примеры CPU/GPU запуска и обработки длинного аудио. В перечне ограничений прямо указаны одновременная речь и переключение казахского/русского. Следовательно, карточка обосновывает выбор казахского кандидата, но не подтверждает качество русского совещания или шала-казахского. Числа автора нельзя выдавать за наши результаты. [Карточка модели](https://huggingface.co/shyngys879/kazakh-whisper-large-v3-turbo)

Рабочий вход приложения: локально декодированный PCM WAV, mono, 16 кГц. Для смешанного сценария не закреплять `language="kk"` для всех записей: это параметр казахского примера автора, а не проверенный универсальный режим. Язык и режим декодирования необходимо записывать вместе с результатом испытания. Времена ASR-сегментов нельзя объявлять точным выравниванием каждого слова. Это рекомендации для нашего конвейера, качество которых предстоит измерить.

В `config.json` на момент проверки указана `transformers_version: "5.9.0"`. Это версия сохранения конфигурации, не самостоятельное доказательство минимально необходимой версии runtime. Не менять проверенное окружение только ради совпадения этой строки; закрепить успешно испытанную версию и ревизию весов. [Конфигурация checkpoint](https://huggingface.co/shyngys879/kazakh-whisper-large-v3-turbo/blob/main/config.json)

### Наблюдение на реальной записи: выбор ASR пересматривается

В диагностическом прогоне команды на полной записи №1 казахский fine-tune вернул всего три чрезмерно длинные реплики с повторениями и бессвязными казахскими/латинскими фрагментами. Из такого транскрипта были получены шесть кандидатов в поручения и успешно создан экспорт. Это подтверждает прохождение программных этапов, но результат не прошёл содержательную проверку: число кандидатов и успешный DOCX/PDF не свидетельствуют о правильности поручений.

Начальные 25 секунд той же записи дали читаемый результат при ручном просмотре. Отдельный поздний фрагмент 220–240 секунд оказался некачественным даже при явном выборе русского языка. Поэтому короткий успешный пример не представлял всю запись, а изменение языка само по себе не устранило отказ. Эти наблюдения являются диагностикой конкретных фрагментов, не рассчитанными WER/CER или общей оценкой качества модели.

У использованного локального HF snapshot в generation config был закреплён `language="kk"`. В адаптере это значение сбрасывается через `model.generation_config.language = None`, чтобы автоматическое определение языка не наследовало настройку fine-tune. Проведённых изменений оказалось недостаточно для пригодного результата на всей записи. Предупреждение автора об ограничениях смешанной речи остаётся релевантным, но оно не доказывает причину данного сбоя. [Ограничения fine-tune](https://huggingface.co/shyngys879/kazakh-whisper-large-v3-turbo#limitations)

Для сравнения используется официальный многоязычный `openai/whisper-large-v3-turbo` с лицензией MIT. Его карточка описывает локальный Transformers-запуск, автоматическое определение языка, последовательную и оконную обработку длинного аудио; также предупреждает о возможных выдуманных и повторяющихся фрагментах. Это обоснованный сравнительный кандидат, но не доказанное исправление. Проверить на тех же полном аудио и проблемном фрагменте, затем отдельно на KK/mixed, прежде чем объявлять выбранной конфигурацией. [Официальная карточка Whisper Large-v3 Turbo](https://huggingface.co/openai/whisper-large-v3-turbo)

## Диаризация: Community-1

Карточка подтверждает локальную загрузку из каталога, обработку mono 16 кГц и вход `{"waveform": tensor, "sample_rate": rate}`. По умолчанию pipeline работает на CPU; GPU включается явно через `pipeline.to(torch.device("cuda"))`. Веса доступны после принятия условий доступа; лицензия модели — CC-BY-4.0. Получаем обычную `speaker_diarization` и дополнительную `exclusive_speaker_diarization`. Первая сохраняет возможность перекрытий; вторую можно использовать для сопоставления с грубыми ASR-временами, сохраняя отдельные признаки неопределённости. Speaker ID не устанавливает личность участника. [Карточка Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1)

Для текущего приложения передавать уже декодированный waveform. Исходник `pyannote.audio` 4.0.0 прямо предусматривает такой путь при неисправной установке torchcodec; ветви чтения waveform возвращают тензор без создания `AudioDecoder`. Формат — `torch.Tensor` размерности `(channels, samples)` и целая частота. Это устраняет зависимость нашего чтения WAV от работоспособности torchcodec, но не удаляет библиотеку из объявленных зависимостей пакета. [Audio I/O в версии 4.0.0](https://raw.githubusercontent.com/pyannote/pyannote-audio/4.0.0/src/pyannote/audio/core/io.py)

В `pyannote.audio` 4.0.0 заявлены Python ≥3.10, torch ≥2.8.0, torchaudio ≥2.8.0, torchcodec ≥0.6.0. Эти нижние границы не являются готовым совместимым lock-файлом. Закрепить полный набор, проверенный на конкретной CUDA/драйвере; не смешивать инструкции 3.x с API Community-1 из 4.x. [Зависимости 4.0.0](https://raw.githubusercontent.com/pyannote/pyannote-audio/4.0.0/pyproject.toml), [изменения API 4.0.0](https://raw.githubusercontent.com/pyannote/pyannote-audio/4.0.0/CHANGELOG.md)

Отключить метрики перед импортом: `PYANNOTE_METRICS_ENABLED=0`. Документация описывает передачу метаданных использования, включая длительность и параметры числа говорящих, при включённой телеметрии. Локальная загрузка модели сама по себе не является проверкой отсутствия исходящих запросов. [Официальное описание телеметрии](https://github.com/pyannote/pyannote-audio#telemetry)

## Извлечение: Qwen3-8B через Ollama

У Qwen3-8B лицензия Apache-2.0. При непосредственном запуске через Transformers автор указывает нижнюю границу 4.51.0; это требование не переносится на наш адаптер Ollama. [Карточка Qwen3-8B](https://huggingface.co/Qwen/Qwen3-8B)

Официальный материал Qwen включает русский и казахский в список языков семейства Qwen3. Это основание попробовать модель, но не метрика точности извлечения поручений из смешанной речи. Проверять отдельно действие, исполнителя, срок, подтверждение и полноту саммари. [Официальное описание Qwen3](https://qwenlm.github.io/blog/qwen3/)

На момент проверки тег Ollama `qwen3:8b` указывает на Q4_K_M, 8,19 млрд параметров и артефакт около 5,2 ГБ. Размер файла не равен требуемой VRAM: память контекста и runtime измеряются отдельно. Для воспроизведения записывать digest установленной модели, версию Ollama и параметры контекста, поскольку тег может измениться. [Артефакт Ollama](https://ollama.com/library/qwen3:8b)

Для извлечения выбрать `think: false` верхнего уровня запроса `/api/chat`, `stream: false`, JSON Schema в `format`; читать JSON из `message.content`. Ollama документирует отдельные поля thinking/content и управление `think`; поддерживаемые значения конкретной модели можно проверить через `/api/show`. Отключение thinking — выбор нашего режима с меньшими накладными расходами, не гарантия лучшей семантической точности. [Thinking API](https://docs.ollama.com/capabilities/thinking)

Ollama принимает схему в `format` и рекомендует проверять ответ через Pydantic. Применить схему ко всем обязательным полям и повторную валидацию на сервере. JSON, соответствующий схеме, всё ещё может содержать неверного человека, срок или цитату: дополнительно проверять ссылки на реплики, оставлять неопределённости и предоставлять правки человеку. Последнее — требование нашего приложения. [Structured outputs](https://docs.ollama.com/capabilities/structured-outputs)

## Локальная загрузка и воспроизведение

Transformers документирует предварительную загрузку `snapshot_download`, `HF_HUB_OFFLINE=1` для запрета HTTP к Hub и `local_files_only=True` в `from_pretrained`. Скачивать модель в тот каталог, который затем указывается в `ASR_MODEL_PATH`: cache по умолчанию и произвольный локальный путь не взаимозаменяемы. [Официальная инструкция offline](https://huggingface.co/docs/transformers/installation#offline-mode)

В `offline_smoke.sh` собственный Ollama запускается с `OLLAMA_NO_CLOUD=1`, отключающим облачные функции, и `OLLAMA_NOPRUNE=1`, запрещающим очистку model blobs при старте в общем хранилище весов. Сетевую изоляцию обеспечивает отдельный Linux network namespace. Команда проверила его создание на Brev; начальный запуск с Ollama 0.34.3 показал неуспешные внешние DNS-попытки внутри изоляции. Наличие изоляции и успех технического конвейера оцениваются отдельно от описанного выше отказа качества ASR. [Настройка cloud features](https://docs.ollama.com/faq#how-do-i-disable-ollama-cloud-features), [официальные переменные Ollama](https://raw.githubusercontent.com/ollama/ollama/main/envconfig/config.go)

Для каждого развёртывания сохранять следующую ведомость рядом с результатом проверки:

| Что фиксировать | Зачем |
| --- | --- |
| ASR/pyannote repository ID, revision, локальный каталог | Повторяемые веса и отсутствие незаполненных путей |
| Ollama version, tag и digest, JSON-схема, generation options | Повторяемый режим извлечения |
| Python, torch, torchaudio, transformers, pyannote.audio, CUDA/драйвер | Восстановление проверенного окружения |
| GPU, peak VRAM, время этапов и длительность аудио | Собственные данные о скорости и памяти |
| Идентификатор/хеш разрешённой записи, язык, ручная разметка | Понятное происхождение результата |

Один активный обработчик остаётся разумным ограничением MVP. Размещение на Brev доказывает возможность работы на этой VM; отдельный запуск на инфраструктуре заказчика и запрет исходящего доступа нужны для утверждения о работе в закрытом контуре.

## Проверки, после которых можно заявлять готовность

1. Прогнать оба MP3 из трека без ручной смены формата, затем разрешённую запись на казахском и смешанную запись с несколькими голосами. Добавить тишину и короткое наложение речи как случаи отказа/неопределённости.
2. Отдельно оценить имена, числа и смысл ASR, границы/метки говорящих, пропущенные и ложные поручения, ответственного и срок. Список участников не использовать как доказательство назначения человека.
3. Проверить предложение без подтверждения, изменённого исполнителя, отсутствующий срок, относительный срок и исходную цитату. Саммари не должно добавлять решения.
4. Исправить результат человеком, сохранить, перезапустить приложение, скачать документы; проверить казахские символы и соответствие сохранённым правкам. При отказе PDF должен оставаться доступный DOCX.
5. После предзагрузки повторить тот же сценарий с запрещённым исходящим доступом. Проверять приложение и локальный Ollama в одинаковых ограничениях; одни переменные Hugging Face не блокируют сеть всего процесса.

Пока этих результатов нет, корректное описание — «локальный конвейер с выбранными кандидатами моделей; качество трёх языковых сценариев проверяется». Маркетинговые заявления карточек и успешная обработка короткого синтетического WAV не заменяют эту проверку.
